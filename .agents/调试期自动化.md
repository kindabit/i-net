# 调试期自动化

调试期自动化是仅在调试构建中可用的本地 HTTP 服务，供外部调试代理（如 LLM 代理）检查与操控应用：读取简化 UI 树、捕获整窗截图、注入原生鼠标与键盘输入。本文档描述启用方式、接口契约与典型用法。

## 启用与安全边界

- 模块仅在 debug 构建且启用 `debug-automation` feature 时参与编译；release 构建即使误带该 feature 也会被 `debug_assertions` 门禁排除，不包含任何痕迹。
- 开发期通过前端脚本启动（等价于 `tauri dev --features debug-automation`）：

  ```bash
  pnpm tauri:dev
  ```

- 服务固定绑定回环地址 `127.0.0.1:17432`，并校验 `Host` 头：仅接受 `127.0.0.1` 与 `localhost`（可带端口、大小写不敏感），其它取值返回 `Forbidden`，以防御 DNS 重绑定。
- 输入注入在操作系统层级合成（Windows 上通过 `SendInput`），会真实操控本机鼠标与键盘；每条注入命令执行前会自动把主窗口置于前台，避免输入泄漏到无关窗口。请在明确知晓这一点时调用。
- 出于数据安全，UI 树**永不返回输入框的当前值**（`value` 被排除在属性白名单之外），输入内容的验证需借助截图或界面状态变化。

## 坐标系

所有端点共用同一坐标系：**主窗口整窗物理像素**。

- 原点是整个应用程序窗口的左上角（含标题栏与边框）。
- 截图像素、UI 树 `bounds`、`/input` 的坐标参数全部使用该坐标系，与显示缩放（DPI）无关：例如 150% 缩放下逻辑尺寸 1024×768 的窗口对应 1558×1208 物理像素。
- `/screenshot` 覆盖整窗（标题栏、边框、webview 内容），不包含窗口阴影。
- 输入坐标由服务端自动加上窗口原点换算为屏幕物理坐标，调用方无需关心显示器布局与多显示器负坐标。

## 通用约定

- 请求与响应均为 JSON（`/screenshot` 为 PNG 二进制），字段名 camelCase。
- 错误统一返回：

  ```json
  {"error":{"code":"BadRequest","message":"commands[1] (mouse_click): count must be within 1..=10"}}
  ```

  错误码与 HTTP 状态：`BadRequest` 400、`Forbidden` 403、`NotFound` 404（保留未用）、`InternalError` 500。`message` 为英文，可安全记录日志。
- 成功响应：`/input` 返回 `204 No Content`。

## GET /health

返回服务存活状态与整窗物理尺寸。

```json
{"version":"0.6.0","width":1558,"height":1208}
```

## GET /screenshot

返回整窗 PNG 截图（`Content-Type: image/png`）。可用于验证输入效果（对话框是否打开、文本是否存在、节点是否移动等）。

## GET /ui-tree

返回当前页面的简化 UI 树：按文档顺序排列的顶层节点数组（美化 JSON）。调用方从节点 `name`、`role`、`text`、`editable` 等字段定位目标，并取 `bounds` 中心作为 `mouse_move` / `mouse_click` 的坐标。

### 节点字段

| 字段 | 出现条件 | 说明 |
|---|---|---|
| `tag` | 必有 | 元素 tag 名；文本节点为 `"#text"` |
| `role` | 有 role 时 | 显式 `role` 属性或按 tag 推断（如 `button`、`textbox`、`dialog`、`listitem`、`link`） |
| `name` | 可访问名称非空时 | 依次取自 `aria-label`、`aria-labelledby`、关联 `label`、`placeholder`、`title`、`alt` 等 |
| `text` | 有可见文本时 | 交互元素的聚合可见文本，或 `#text` 节点的文本；最长 80 个 Unicode 码点 |
| `editable` | 为 true 时 | 元素接受可编辑文本 |
| `focusable` | 为 true 时 | 元素可聚焦 |
| `bounds` | 必有 | `{left, top, width, height}`，窗口物理像素整数 |
| `states` | 元素节点必有 | `disabled`、`checked`、`selected`、`focused` 始终存在；`expanded` 仅在 `aria-expanded` 显式出现时为布尔值；`#text` 节点没有 `states` |
| `attrs` | 白名单属性非空时 | `data-id`、`data-nodeid`、`data-handleid`、`data-handlepos`、`placeholder`、`title`、`alt`、`href`、`type`，以及全部 `aria-*` 属性；**不含 `value`** |
| `children` | 子节点非空时 | 与顶层同构的节点数组 |

### 节点类别

- **交互元素（action-leaf）**：按钮、链接、输入框、勾选框、滑块等。不展开内部子树，`text` 为子树聚合后的可见文本，因此按钮的文字与其点击区域一同出现。
- **复合控件与容器**：列表、菜单、树条目、对话框、表格等按原结构展开子节点。
- **文本节点**：`#text`，`bounds` 由 DOM Range 测量所得。
- **布局元素**：无语义且不可交互、不可编辑的包装元素不贡献节点，其子孙节点会提升到最近的保留祖先（因此子节点以数组形式挂在父节点下）；例外：可拖拽元素与携带 `data-handleid` / `data-handlepos` 的连接桩会保留为节点，以便定位拖拽手柄等交互位置。

### 可见性与过滤

- 跳过 `HEAD`、`SCRIPT`、`STYLE`、`NOSCRIPT`、`TEMPLATE`、`LINK`、`META`、`BR`、`HR`。
- `display:none`、`visibility:hidden` 等被 `checkVisibility` 判定为不渲染的子树被跳过（`opacity:0` 有意忽略；`display:contents` 容器继续遍历）。
- `aria-hidden="true"` 或 `inert` 的子树被跳过。
- 遮挡过滤：对节点矩形取内缩 1px 的四角与 3×3 网格中心共最多 13 个采样点做命中测试，全部被无关悬浮层（如对话框遮罩）覆盖的节点被丢弃；视口之外的采样点被忽略，完全滚出视口的内容仍会保留。例外：`role="tooltip"` 的悬浮子树在其可见期间豁免遮挡判定（其内容为 `pointer-events:none`），未显示时内容为 `display:none`，仍不产生节点。
- 既无子节点又无 `name` 的容器、零尺寸且无 `name` 与 `text` 的交互元素被丢弃。

### 示例

```json
[
  {
    "tag": "INPUT",
    "role": "textbox",
    "name": "数据库名称",
    "editable": true,
    "focusable": true,
    "bounds": { "left": 395, "top": 579, "width": 690, "height": 84 },
    "states": { "disabled": false, "checked": false, "selected": false, "focused": true },
    "attrs": { "aria-labelledby": "input-v-3-label", "type": "text" }
  },
  {
    "tag": "BUTTON",
    "role": "button",
    "name": "确认",
    "text": "确认",
    "focusable": true,
    "bounds": { "left": 1091, "top": 591, "width": 72, "height": 72 },
    "states": { "disabled": false, "checked": false, "selected": false, "focused": false }
  }
]
```

## POST /input

按数组顺序串行执行一批输入命令。

```bash
curl -X POST http://127.0.0.1:17432/input \
  -H "Content-Type: application/json" \
  --data-binary @commands.json
```

```json
{"commands":[
  {"kind":"mouse_move","x":740,"y":621},
  {"kind":"mouse_click","button":"left","count":1},
  {"kind":"key_click","keys":["Control","a"]},
  {"kind":"type","text":"hello"},
  {"kind":"wait","duration":300,"unit":"ms"}
]}
```

### 命令一览

判别字段为 `kind`（snake_case），各命令参数为 camelCase。

| kind | 参数 | 语义与约束 |
|---|---|---|
| `mouse_move` | `x`、`y`（必填，窗口物理像素） | 以配置速度沿直线平滑移动光标；距离为 0 时不移动 |
| `mouse_press` | `button`（`left`/`right`，默认 `left`） | 在当前光标位置按下；不检查此前是否已按下 |
| `mouse_release` | `button`（同上） | 在当前光标位置松开；不检查此前是否已松开 |
| `mouse_click` | `button`（默认 `left`）、`count`（1..=10，默认 1） | 快速按下并松开 `count` 次；每次按下保持 `mouseClickSpan`，相邻两次点击间隔固定 50ms |
| `mouse_scroll` | `direction`（`up`/`down`/`left`/`right`，必填）、`amount`（1..=1000 刻度，必填） | 在当前光标位置滚动；每个刻度间隔 10ms |
| `mouse_drag` | `from`、`to`（必填，`{"x":..,"y":..}`）、`button`（默认 `left`） | 平滑移动到起点 → 按下前抖动 2px → 按下 → 按速度直线插值移动到终点 → 停顿 80ms → 松开；抖动与停顿保证 webview 的原生 HTML5 拖放可靠启动 |
| `key_press` | `keys`（1..=8 个按键名，必填） | 按数组顺序依次按下且保持按下 |
| `key_release` | `keys`（1..=8，必填） | 按数组顺序依次松开 |
| `key_click` | `keys`（1..=8 且不得重复，必填）、`count`（1..=10，默认 1） | 整个序列重复 `count` 轮；每轮按序按下全部按键 → 保持 `keyClickSpan` → 按数组顺序（FIFO）松开；轮内相邻按键间隔 `keyClickInTurnInterval`，轮间间隔 `keyClickCrossTurnInterval` |
| `type` | `text`（必填，不得含空字节） | 注入 Unicode 文本，适合中文、emoji 等键盘布局无法直接产生的字符 |
| `wait` | `duration`（非负整数，必填）、`unit`（`ms`/`s`，默认 `ms`） | 等待指定时长；上限 60 秒 |
| `config` | 见下表，全部可选 | 修改本次请求内后续命令的执行配置 |

按键名不区分大小写并支持常见别名：`Control`/`Ctrl`、`Shift`、`Alt`、`Meta`/`Win`、`Enter`、`Escape`、`Tab`、`Space`、`Backspace`、`Delete`、`Home`、`End`、`PageUp`/`PageDown`、方向键（`Up`/`Down`/`Left`/`Right`，也接受 `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` 等 W3C 键名）、`F1`~`F20`、`Numpad0`~`Numpad9` 等；单个字符（如 `"a"`、`"1"`）按当前键盘布局输入。

### config 配置项

修改仅对**本次请求内其后的命令**生效，请求结束后恢复默认值。

| 字段 | 默认值 | 范围 | 作用 |
|---|---|---|---|
| `mouseClickSpan` | 50ms | 0..=5000 | `mouse_click` 每次按下与松开之间的时长 |
| `mouseMoveSpeed` | 1500 物理像素/秒 | 50..=20000 | `mouse_move` 与 `mouse_drag` 的直线移动速度 |
| `keyClickInTurnInterval` | 10ms | 0..=1000 | `key_click` 一轮内相邻按键按下或松开之间的间隔 |
| `keyClickCrossTurnInterval` | 50ms | 0..=5000 | `key_click` 相邻两轮之间的间隔（上轮最后一个按键松开到下轮第一个按键按下） |
| `keyClickSpan` | 50ms | 0..=5000 | `key_click` 一轮中全部按键按下后保持的时长 |
| `commandInterval` | 0ms | 0..=5000 | 相邻两条命令之间的额外间隔；首条命令之前不插入 |

### 队列语义

- 命令数量 1..=256，串行执行；整个队列共用一个原生输入实例。
- **失败即停**：任一命令失败时停止执行，返回对应错误码，`message` 前缀带 0 基索引与命令名，例如 `commands[2] (mouse_drag): x coordinate is out of range`。
- **自动释放**：失败返回前，会尽力释放本次请求中仍处于按下状态的鼠标按键与键盘按键（键盘按后进先出），释放失败不覆盖原始错误，避免按键卡住。
- **请求间按键状态**：每个请求独占一个原生输入句柄，请求结束（无论成败）后其中仍按下的按键会被释放；需要在多次操作之间保持按键（例如按住 Alt 拖拽节点）时，必须把按下、操作与松开放在同一个请求内。
- 移动类命令按不超过 15px 的步长做直线插值（最少 8 步、最多 1000 步），每步间隔为 `15px ÷ mouseMoveSpeed`（默认约 10ms/步）；单次移动预计超过 60 秒时报 `BadRequest`。
- 单条命令失败不会影响服务本身，后续请求可正常下发。

## POST /shutdown

请求关闭应用：先返回 `204 No Content`，随后应用按正常退出流程（保存偏好与元数据）自行退出。用于测试结束后关闭应用，避免依赖平台相关的进程管理命令。

```bash
curl -X POST http://127.0.0.1:17432/shutdown
```

## 典型工作流

1. `GET /ui-tree` 定位目标：按 `name`/`text`/`role` 查找，取 `bounds` 中心作为坐标。
2. `POST /input` 下发命令队列：先 `mouse_move` 再点击类命令；键盘输入前先聚焦目标输入框。
3. `GET /screenshot` 验证视觉结果；或再次 `GET /ui-tree` 比对 `bounds`、`states`（如 `selected`、`focused`、`disabled`）变化。
4. 失败时读取错误 `message` 中的 `commands[i] (kind)` 定位命令并用 `/ui-tree` 重新获取坐标（对话框动画期间坐标会漂移，建议等待动画结束后再定位）。

## 数值契约速查

| 项目 | 上限 |
|---|---|
| 队列命令数 | 256 |
| `mouse_click` / `key_click` 的 `count` | 10 |
| `key_press` / `key_release` / `key_click` 的按键数 | 8 |
| `mouse_scroll` 的 `amount` | 1000 刻度 |
| `wait` 时长 | 60 秒 |
| 单次平滑移动预计时长 | 60 秒 |
| 文本字段输出长度 | 80 个 Unicode 码点 |

## 调用提示

- Windows PowerShell 直接内联 `-d '{"...":"..."}'` 时双引号会被剥离导致 JSON 解析失败；建议使用 `--data-binary @file.json`，或改用 Node/其它宿主发送请求。
- 调试注入会真实占用鼠标与键盘，执行期间请勿操作本机，并避免在无人看守时运行长队列。
- UI 树中的坐标有大约一帧的时效性：界面动画（对话框打开、画布缩放）结束后坐标才稳定，连续操作之间可插入 `wait` 或轮询 `/ui-tree`。
- `/screenshot` 返回的画面相对 UI 树状态存在约一帧的渲染延迟（例如面板切换过渡期间可能截到旧画面）；以截图作为留档或像素比对时，应先等待目标状态稳定（动画结束、元素持续存在）再截图。
