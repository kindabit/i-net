# 实际运行

- 入口（ main.rs -> lib.rs ）
    - 插件注册
    - command 注册
    - setup
        - 初始化数据目录
        - 初始化日志功能
        - 设置全局 path 状态
        - 初始化 preference （和 preference service 交叉）
            - 设置全局 preference connection 状态
        - 初始化 metadata （和 metadata service 交叉）
            - 设置全局 metadata connection 状态
    - app 生命周期
        - 退出时
            - 保存 preference （和 preference service 交叉）
            - 保存 metadata （和 metadata service 交叉）
            - 保存用户数据库（若处于打开状态，和 user_database service 交叉）
- 通用业务模块（ common.rs ）跨多个模块，耦合度的集中点
    - 数据库连接业务模块（ connection.rs ）依赖数据版本业务模块，被各个专项业务模块使用
    - 数据版本业务模块（ data_version.rs ）通过数据库连接业务模块透明渗透至各个专项业务模块
- 专项业务模块（ business.rs ）模块之间无源码间依赖，保持低耦合度
    - 应用信息业务模块（ app_info.rs ）向关于对话框提供编译期确定的应用元数据
    - 用户偏好业务模块（ preference.rs ）
        - 全局状态（ state.rs ）
        - 初始化（ initialize.rs ）
        - 持久化（ save.rs ）
        - 读写（ get.rs / set.rs ）
    - 元数据业务模块（ metadata.rs ）
        - 全局状态（ state.rs ）
        - 初始化（ initialize.rs ）
        - 持久化（ save.rs ）
        - 注册、列表、归档、物理删除（ register.rs / list.rs / archive.rs / physical_delete.rs ）
    - 备份业务模块（ backup.rs ）全量备份与还原数据目录（除 logs/ 外）
        - 备份文件格式 [Header (64B) | Shard 校验和表（变长）| Shard 区（变长）]
        - 前端进度提示
        - 打包/解包
        - 包体校验
        - 备份包体积预测
    - 内存刷新模块（ reclaim.rs ）用于通知各业务模块磁盘文件已刷新，需要重新读取（避免关闭应用程序时用旧数据覆盖磁盘里的新数据）
        - reclaim_preference：重新读取 preference 数据库磁盘文件，替换内存 connection
        - reclaim_metadata：重新读取 metadata 数据库磁盘文件，替换内存 connection
        - reclaim_user_database：若 user_database 处于打开状态则强制关闭
    - 受控崩溃（ fatal_exit.rs ）前端通过调用该接口触发整个应用程序的受控崩溃
    - 用户数据库业务模块（ user_database.rs ）
        - 状态（ state.rs ）connection + metadata + key 三个全局静态量
        - 实体模块，除了实体类型外还有以下特殊对象
            - 根画布的名称
            - 画布宇宙的画布 id 特殊值（用于视口）
            - 日志的 Action 类型和记录节点字段变化的 NodeFieldChange 类型
        - 子业务模块
            - 注册表（ registry ）
                - 初始化
                - 读/写
            - 生命周期（ lifecycle ）
                - 初始化（创建目录结构和用户数据库文件，建表时和其它所有子业务模块交叉，设置状态，并且在获取用户数据库元数据时和 metadata 模块交叉）
                - 保存、关闭
            - 字段类型（ field_type ）支撑 node_field 、 template 和 log 模块
                - JSON Schema 的后端封装与校验（ schema.rs ）
                - 类型系统的内部能力（ catalog.rs ）
                - 字段值加解密（ codec.rs ）
                - 传输层字段值类型定义（ field_value.rs ）
            - 画布（ canvas ）
                - 初始化（除了建表以外，还会插入根画布）
                - 新建、移动、恢复（级联删除，调用 node dao 连带恢复引用节点）、列表
                - 重命名（画布节点的标题与画布名称始终保持一致）
                - 逻辑删除（级联逻辑删除子画布，调用 node dao 级联逻辑删除所有引用节点，不修改其它的节点和边）
                - 物理删除（级联物理删除子画布、画布内的所有节点和边以及相关视口，调用 node dao 物理删除引用该画布的节点）
                - 获取画布色彩列表，设置画布节点色彩
                - 批量移动画布（用于自动布局）
            - 视口（ viewport ）
                - 初始化
                - 读写（画布宇宙视口用特殊 canvas_id）
            - 字典（ dictionary ）
                - 初始化
                - 列表（全量返回）
                - 全量覆盖写（删除字典直接将关联的模板字段和节点字段的 dictionary_id 置空）
            - 附件（ attachment ）
                - 初始化
                - 导入、导出、调整顺序（导入时明文经 util/compress 压缩 guard 后再加密）
                - 获取附件元数据（用于导出时预填文件名称，为数不多的 command 函数直接调用 service 函数的地方）
                - 读取附件列表、读取孤儿文件（有文件没元数据）列表
                - 逻辑删除、恢复、物理删除、删除孤儿文件
                - 加载明文数据（解密后若 compressed 为 true 再经解压 guard 还原）
                - 更新附件文件（经压缩 guard 后重新加密，同步刷新 compressed 与 compress_param）
            - 模板和模板字段（ template ）
                - 初始化（建 template 和 template_field 表）
                - 新建、从节点创建
                - 重命名
                - 物理删除
                - 列表
                - 读字段（反序列化 type_config ）
                - 写字段（校验、全量覆盖、序列化 type_config ）
                - 导入和导出
            - 节点（ node ）
                - 初始化
                - 新建（可传入模板 id 以及是否创建新的子画布）、移动、恢复（调用 canvas service 级联恢复引用的画布）、列表（返回 NodeVO ，影子节点沿产生边链级联合并根本体节点的展示数据）
                - 修改（画布节点的标题与画布名称始终保持一致）
                - 复制（相当于使用模板创建新节点）
                - 逻辑删除（只动这个节点，不动边，恢复后相连的边自动重新显示，调用 canvas service 级联逻辑删除引用的画布）
                - 物理删除（物理删除节点，同时删除所有相连的边和节点字段，级联物理删除引用的画布；影子双阶段确认：相连边删除引发影子级联坍塌）
                - 关键词搜索（和 canvas 交叉；影子节点不参与搜索）
                - 获取节点色彩列表，设置节点色彩
                - 批量移动节点（用于自动布局）
                - 批量跨画布迁移节点
                - 影子节点（指向产生它的边，生命周期完全由边控制：边删除时影子级联删除，下游嵌套影子递归坍塌；只有位置与 shadow_id 是自有数据，展示数据从根本体节点拉取；分两类：入向影子是普通节点的影子、只能作连线的源，出向影子是画布节点的影子、只能作连线的目标；无法对其进行编辑或其它写入操作；允许嵌套成影子链）
                - 影子断连收集：沿"边→产生的影子→影子的相连边→嵌套影子"递归预收集边删除时将失去连接的节点标题，供删边、反向替换与物理删除节点复用；影子方向必然可推导（由产生边源端是否为画布节点决定），邻居必然非影子，任何不一致都返回 DataCorruption* 错误
            - 节点字段（ node_field ）
                - 初始化
                - 读（值解密，反序列化 type_config 为 raw json value ）
                - 写（校验、加密、序列化 type_config 、全量覆盖、 diff 生成日志）
            - 边（ edge ）
                - 初始化
                - 新建（同向已有边时直接更新连接桩；反向已有边时执行删旧建新替换）
                - 删除（影子随边级联删除，嵌套影子沿外键链递归坍塌；断连检测递归覆盖下游各级画布）、列表
                - 更新（标题和详情）
            - 导出（ export ）
                - 后端国际化
            - 日志（ log ）
                - 初始化
                - 新增（将 Action 拆分后组装 Log 入库）
                - 分页列表（从 Log 重组 Action 构造 LogListResponse 返回）
- 全局状态
    - 用户偏好数据库连接（ preference::state ）程序启动时初始化，运行时在内存中读写，随时可保存，程序关闭时也会保存
    - 元数据数据库连接（ metadata::state ）程序启动时初始化，运行时在内存中读写，随时可保存，程序关闭时也会保存
    - 用户数据库连接（ user_database::state ）打开数据库时初始化，关闭之前在内存中读写，随时可保存，程序关闭时如果处于打开状态也会保存
        - 用户数据库连接
        - 关于这个用户数据库的元数据
        - 密钥

# 边和影子节点的规则和含义

影子节点是因为边存在而存在的，所以影子节点引用边而不是节点，这样即使存在多重级联关系，只要删除最初的那一条边，整个级联体系都能自然地被连根拔起。

|节点相连作用关系|普通节点（目标）|画布节点（目标）|普通节点的影子节点（目标）| 画布节点的影子节点（目标）|
|-|-|-|-|-|
|普通节点（源）|无级联影响（含义为“目标依赖源”）|在目标画布创建源普通节点的影子节点（含义为“目标画布中的节点可能需要依赖该源普通节点”）|非法连接（普通节点的影子节点现在只能是入向影子节点，无法作为目标）|向上查找目标影子节点的本体画布，在本体画布创建源普通节点的影子节点（含义为“目标节点的本体画布中的节点可能需要依赖该源普通节点”）|
|画布节点（源）|非法连接（见备注1）|在源画布节点创建目标画布节点的影子节点（含义为“目标画布中的节点可能需要依赖源画布中的节点，因此需要在源画布中创建目标画布的影子节点，以便所需依赖项进一步在目标画布中建立影子节点”）|非法连接（普通节点的影子节点现在只能是入向影子节点，无法作为目标）|向上查找目标影子节点的本体画布，在源画布中创建指向目标本体画布的影子节点（含义类似“画布节点（源） -> 画布节点（目标）”，但是多一层“目标画布中的节点可能需要依赖源当前画布的子画布中的节点”的含义）|
|普通节点的影子节点（源）|无级联影响（含义为“目标依赖源影子节点的本体”）|在目标画布节点创建影子节点的影子节点（含义为“目标画布中的节点可能需要依赖源影子节点所指的普通节点”）|非法连接（普通节点的影子节点现在只能是入向影子节点，无法作为目标）|非法连接（目标的本体或者上级影子节点直接或间接地存在于父画布中，源的本体或者上级影子节点也直接或间接地存在于父画布中，如果两者需要连接，应该直接在父画布中连接，而不是先接入子画布再连接）|
|画布节点的影子节点（源）|非法连接（画布节点的影子节点现在只能是出向影子节点，无法作为源）|非法连接（画布节点的影子节点现在只能是出向影子节点，无法作为源）|非法连接中的非法连接|非法连接（画布节点的影子节点现在只能是出向影子节点，无法作为源）|

备注1：这意味着目标普通节点需要依赖源画布中的节点。我们不允许在源画布中建立目标普通节点的影子节点，因为这可能会导致目标普通节点的依赖项散落在各个不同的画布中，而我们希望依赖项能够集中显示在目标节点的周围，从而避免用户需要一个画布一个画布地查看依赖情况。如果遇到这种需要依赖子画布中的节点的情况，应该先新建一个子画布，然后将目标普通节点放进新的子画布中，再将源画布节点和新的子画布节点相连，这样源画布中就会出现新的子画布的影子节点，然后再在源画布中将目标普通节点需要依赖的源普通节点与新的子画布的影子节点相连，这样新的子画布中就会出现所需源普通节点的影子节点，最后再将源普通节点的影子节点与依赖它的目标节点相连。
