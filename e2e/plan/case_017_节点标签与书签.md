# case_017 节点标签与书签

## 测试主题

验证「节点标签与书签」功能的完整链路：编辑节点对话框内的书签切换与标签输入（自由输入、空白/重复规整）、数据节点卡片书签图标、书签列表对话框（按画布分组、组内编辑与跳转、空态、编辑后整表重载与画布同步）、标签云面板（空态、标签按钮、字号分档、与模板/回收站面板互斥）、标签分组列表对话框（标题、分组、关闭后标签云重载）、全局搜索的标签匹配与根画布本地化显示、日志中 NodeTagsModify / NodeBookmarkModify 的名称与详情文案。

## 前置条件

- 复制 fixture `base` 到 `<case>\output\data` 并以该目录启动应用
- 解锁 `zz-e2e-base` / `e2e-password`，位于根画布（fixture `lastScene` 指向根画布）
- 界面语言：中文（fixture 未固定语言，脚本先确保中文）
- fixture 必须由当前源码重建（`node e2e\script\_fixtures\build.js`）：旧 fixture 的用户数据库缺 `node.bookmarked` 列与 `node_tag` 表，节点列表查询会失败、根画布不显示节点
- fixture 根画布节点：「账号 A」（卡片 bounds 约 699,368,200×100）与「备注 B」（约 1074,643），二者之间一条无标签边；初始无任何标签与书签
- 测试机 DPI 缩放 1.25：数据节点卡片 160×80 CSS = 200×100 物理像素；窗口 1298×1007，坐标按 `/health` 与 UI 树动态读取，不硬编码
- 本用例新增的画布数据节点「新画布」（落点 350,400）与子画布内节点「新节点」（落点 800,600）均落在脚本指定的空白落点

## 备注与风险

- **UI 树不可见项**：标签 chip 不产生独立节点，chip 文本聚合进 combobox 的 `text`（实测值「重要 标签」），断言「聚合文本中目标标签恰好出现一次」；书签图标是无 title 的 VIcon（布局元素不产生 UI 节点），用截图像素计数断言（实测：无图标基线 68、收藏后 234、取消后 68，判据取「收藏后 ≥ 基线+100」「取消后 ≤ 基线+40」）
- **combobox 回车行为**：Vuetify multiple combobox 输入文本后 Enter 生成 chip；重复值由应用层 `watch(normalizeTags)` 去重、纯空白被丢弃，UI 最终每个标签只有一个 chip
- **嵌套对话框**：书签列表内点击编辑会叠加编辑对话框（persistent，Esc 不关闭）；`findDialog` 取面积最小者，关闭编辑对话框后列表重新加载
- **同名按钮定位**：书签/标签列表对话框中每行都有「编辑节点」「跳转到节点」按钮，必须按节点标题文本的垂直位置选取同行按钮，不能取 `findAttr` 的首个命中
- **标签云关闭方式**：面板 `v-click-outside=close`，工具栏按钮是 toggle；脚本用工具栏按钮切换，避免鼠标误入画布触发关闭
- **分组排序**：组间按画布名 `localeCompare` 升序；实测顺序为「根画布」在「新画布」前，与脚本内 `localeCompare` 计算结果一致，不硬编码字符串顺序
- **跳转居中容差**：沿用 case_010 的「画布区域（顶部条以下）中心 ±20%」判据；实测「新节点」文本中心 (636.5, 503.5) 与区域中心 (649, 526) 偏差 (12.5, 22.5)
- **日志详情标点**：全角顿号「、」连接数组项、空数组显示「—」、中文引号“ ”；本用例文案远小于 `text` 80 码点上限
- **日志条目与裁剪**：日志列表会被滚动容器裁剪，且历史 fixture 构建日志使本用例日志总数超过首屏可见条数；用日志对话框自带的「搜索日志内容」按关键词过滤后再断言详情，避免依赖滚动
- **S6 搜索防抖**：搜索请求带 300ms 防抖，断言用等待函数而非固定 sleep
- **S7 子画布构造成本**：模板拖拽创建「新画布」并钻入属既有能力（case_016 已覆盖），本用例复用同一路径
- **旧 fixture 不兼容**：旧 fixture 的用户数据库是新增书签列与 node_tag 表之前的 schema，打开后节点列表查询失败、画布无节点；执行阶段已用 `node e2e\script\_fixtures\build.js` 重建（fixture 的 node 表含 bookmarked 列，见修订记录）
- **S2 取消不写库的可观测性**：取消分支没有直接副作用可观测（后端无变化时也不写日志），由「S3 标签云状态保持」「S4 书签列表状态保持」「S9 日志计数」间接佐证，`coverage.md` 中记录
- **F4 影子节点只读**：UI 不可达，已在 `coverage.md` 注明

## 修订记录

1. **fixture 重建**（环境前置修正，2026-09-22）：执行阶段发现旧 fixture 数据库缺 `node.bookmarked` 列与 `node_tag` 表，解锁后根画布不显示任何节点（节点查询失败）。按 `_fixtures\README.md` 的流程用 `node e2e\script\_fixtures\build.js` 在调试包上重建 fixture；重建后的 fixture 内容与文档描述一致（根画布、「账号 A」、「备注 B」、一条边、lastScene 根画布）。前置条件一节据此补充重建要求。
2. **chip 断言方式修正**（测试设计修正）：实测标签 chip 在 UI 树中不产生独立节点，其文本聚合进标签 combobox 的 `text`（如「重要 标签」）；S1/S2/S4 中「chip 出现/回填」改为断言 combobox 聚合文本中目标标签恰好出现一次。
3. **书签图标像素判据标定**（测试设计修正）：实测基线（无图标）68、收藏后 234、取消后 68；判据由「显著上升」量化为「收藏后 ≥ 基线+100」「取消后 ≤ 基线+40」，并补充「点击空白取消选中后再截图」以排除选中边框的蓝色像素干扰。
4. **S8 跳转按钮按行定位**（测试设计修正）：书签列表每行都有「跳转到节点」按钮，首个命中者会点到「备注 B」行导致跳转目标错误；改为按「新节点」标题文本的垂直位置选取同行按钮。
5. **S9 改为关键词过滤后断言**（测试设计修正）：日志总数含 fixture 构建日志且超过首屏可见条数，列表裁剪会使早期条目从 UI 树消失；改为在日志对话框内按「账号」「备注」「新节点」分别搜索过滤后再断言详情文案。
6. **实测确认项**：标签云空态「暂无标签」；标签云与模板面板双向互斥；「标签：重要」分组对话框含「账号 A」与「根画布」且 Esc 关闭后标签云仍在；书签列表嵌套编辑取消书签后重载为「暂无书签节点」；标签云双标签高度 33 vs 24 物理像素；搜索「重要」命中「账号 A」「备注 B」且副标题为「空节点 · 根画布」；书签分组顺序「根画布」先于「新画布」；跳转后居中偏差 (12.5, 22.5)；日志三类详情的实际渲染文本与契约逐字一致。
7. **脚本运行期修正**（形成脚本阶段）：
   - 编辑对话框的「取消」按钮曾用包含匹配命中「取消书签」按钮（点击后对话框不关闭），改为 `exact: true` 的精确子树文本匹配；「确认」「关闭」按钮同步改为精确匹配；
   - S8 的书签列表断言原写作「三个节点（含备注 B）」有误：S5 只给「备注 B」加了标签而未加书签，列表本不应包含它；修正为「账号 A、新节点」两个书签节点，并补充「仅有标签未收藏的『备注 B』不出现在书签列表」的负面断言；
   - 修正后连续两次运行 PASS（50 checks）。
8. **removed 非空路径不可达**（覆盖局限）：NodeTagsModify 的移除路径（removed 非空）需要在编辑对话框删除已有标签 chip，而 chip 及其关闭图标位于 action-leaf combobox 内部、UI 树不展开，无法稳定定位；本用例仅覆盖新增路径（removed 为空显示「—」）。后端 `set_for_node` 的 added/removed 差集计算由单元测试覆盖，`coverage.md` 中记录该限制。
