# case_013 归档与删除数据库（修订版）

> 本文件是 `case_013_归档与删除数据库.md` 的修订版，记录并固化了与实测一致的计划内容；
> 修订点见文末「修订记录」。正式脚本：`e2e\script\case_013\case_013.js`。

## 测试主题

在首页归档管理对话框中完成数据库的归档、解除归档与永久删除：归档后首页候选消失、元数据状态展示、删除对话框的名称确认与密码校验两类失败路径、以及成功删除后数据目录清理。本用例验证「归档 → 候选过滤 → 解除归档 → 物理删除」链路。

## 前置条件

- 复制 fixture `base` 到 `<case>\output\data` 并以该目录启动应用
- 不需解锁数据库；停留在首页（界面语言中文，出现「数据库名称」输入框）
- 记录启动前 `<case>\output\data\user_database_set\` 下的数据库目录名（uuid），用于删除后比对
- 删除成功后 `user_database_set\` 变为空目录（实测该目录下唯一子目录被清除）

## 覆盖范围

前端功能点：
- 首页 `aria-label="数据库归档与删除"` 按钮打开「归档管理」对话框
- 列表项：数据库名称、副标题「状态 · 最后打开时间」（状态为「已归档」/「未归档」）
- 未归档项只有「归档」按钮；已归档项显示「解除归档」与「删除」按钮
- 归档/解除归档成功 snackbar；列表状态即时更新（无需关闭重开对话框）
- 关闭对话框后首页候选列表刷新（归档数据库不出现在候选中）
- 删除数据库对话框：标题「删除数据库」、正文、「请输入数据库名称以确认」输入、「数据库密码」输入、「确认删除」按钮可用条件（名称匹配且密码非空）
- 删除失败提示（密码错误）与成功 snackbar「数据库“…”已删除」
- 删除对话框在点击「确认删除」后立即关闭（不等待后端结果）；失败时由归档管理对话框承接后续操作

后端命令（经由 UI 触发）：
- `metadata_list`（打开对话框时分别查询归档/未归档列表；首页刷新候选）
- `metadata_archive`（归档与解除归档）
- `metadata_save`（归档/删除后的异步落盘）
- `metadata_physical_delete`（归档前置 + 密码校验 + 删除数据库目录）

## 备注与风险

- 删除数据库必须先归档：归档管理对话框对未归档项不渲染「删除」按钮，因此「未归档删除」只能由后端错误码兜底，不在 UI 触达范围。
- 名称不匹配时**没有错误文案**，仅有按钮禁用；断言以「按钮 `disabled` 状态保持 true」为准。
- 密码校验由后端实际解密数据库文件完成；实测错误密码返回 `FailToDecrypt` → 文案「密码错误」（与原文案预期一致，无偏差）。
- **删除对话框的关闭时机（实测）**：`DeleteDatabaseDialog` 的「确认删除」处理器先 `emit("confirm", …)` 再 `close()`，因此对话框在提交瞬间关闭，与后端结果无关；失败路径下由「归档管理」对话框保持打开承接重试（原计划「删除对话框保持打开」与实现不符，已按实测固化）。
- 归档与解除归档后前端调用 `metadata_save`（异步 fire-and-forget），本用例不断言其落盘时机。
- 本用例会删除 fixture 数据（用例数据目录独立，不影响其它用例）；执行后不再对该数据库做其它断言。
- `metadata_physical_delete` 在数据库文件不存在时会跳过密码校验（仅校验归档标志），属防御路径，不构造。
- 「删除」按钮的 error 色不在 UI 树属性中暴露，脚本以截图像素统计断言（删除按钮区域红色像素数量显著高于「解除归档」按钮，后者为 0）。

## 修订记录

1. **步骤 8 预期修正（核心偏差）**：原计划预期密码错误时「删除对话框保持打开」；实测（并核对
   `src\views\HomeComponents\DeleteDatabaseDialog.vue` 的 `onConfirm`：`emit("confirm"); close();`）
   对话框在点击「确认删除」后立即关闭。修订为断言「删除对话框关闭、归档管理对话框保持打开、
   数据库行与数据目录不变」。后端 `FailToDecrypt` →「密码错误」与原文案预期一致。
2. **步骤 9 修正**：因步骤 8 后删除对话框已关闭，原计划「将密码清空重输」不可达；修订为
   「重新点击『删除』打开删除对话框，再输入名称与正确密码」。
3. **F4 位置修正**：原计划「8 之后点击『取消』」在删除对话框已关闭时不可达；修订为步骤 8b：
   重新打开删除对话框（顺带断言输入重置与「确认删除」禁用）再点击「取消」，验证对话框关闭、
   数据库保留在归档列表。
4. **步骤 2 补充 error 色断言**：原计划仅以截图留档「删除」为 error 色；修订为对删除按钮与
   解除归档按钮区域做像素统计（删除按钮红色像素 ≥ 阈值、解除归档按钮红色像素为 0）并保留截图。
5. **步骤 4 的候选为空口径**：明确断言「无匹配项」文案出现且候选列表项数量为 0（不依赖下拉
   收起状态），并轮询等待首页元数据刷新完成。
6. **F3 固化**：未归档行按钮断言语义并入步骤 1（仅「归档」）与步骤 5（「删除」消失）。
7. **删除后目录状态**：实测 `user_database_set\` 变为空目录；脚本按「uuid 子目录不存在」断言
   （不以目录整体消失为条件）。
