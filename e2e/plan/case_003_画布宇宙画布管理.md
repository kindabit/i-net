# case_003 画布宇宙画布管理（修订版）

> 本文件是 `case_003_画布宇宙画布管理.md` 的修订版：在执行计划主流程实测后，修正了与实现不一致的测试条件。修订点见文末「修订记录」。

## 测试主题

在画布宇宙中管理画布：从根画布返回宇宙、在画布内创建子画布（画布数据节点）、对子画布重命名/配色/逻辑删除/回收站恢复/永久删除、自动布局，以及宇宙视口缩放持久化。本用例验证「画布层级创建 → 宇宙管理 → 视口状态保持」链路。

## 前置条件

- 复制 fixture `base` 到 `<case>\output\data` 并以该目录启动应用
- 解锁 `zz-e2e-base` / `e2e-password`，解锁后位于根画布（fixture `lastScene` 指向根画布；若停在画布宇宙则先双击「根画布」进入）
- 界面语言：中文

## 覆盖范围

前端功能点：
- 面包屑「画布宇宙」返回宇宙；双击画布节点进入画布
- 画布内模板面板「拖拽创建画布数据节点」手柄创建子画布，子画布在宇宙中作为画布节点出现
- 画布节点 hover 按钮组：重命名画布、自定义颜色、删除画布（根画布只显示自定义颜色）
- 重命名画布对话框（画布名称唯一性由后端校验）
- 自定义画布节点颜色对话框（预设组合选择与保存）
- 画布逻辑删除与画布回收站面板：恢复画布、永久删除、清空回收站入口
- 自动布局按钮（布局后画布坐标变化）
- 宇宙视口缩放/平移持久化（进入画布再返回后保持）
- 画布节点拖拽移动（`user_database_canvas_move_canvases`）

后端命令（经由 UI 触发）：
- `user_database_node_create`（`createCanvas=true` 创建画布数据节点与子画布）
- `user_database_canvas_list`（宇宙加载、回收站面板加载 `deleted=true/false`）
- `user_database_canvas_rename`、`user_database_canvas_logical_delete`、`user_database_canvas_restore`、`user_database_canvas_physical_delete`
- `user_database_canvas_move_canvases`（拖拽与自动布局）
- `user_database_canvas_node_set_color`、`user_database_canvas_node_color_list`（配色对话框）
- `user_database_viewport_get` / `user_database_viewport_set`（宇宙视口，canvasId 为 null）

## 备注与风险

- 画布节点**没有右键菜单**（右键仅阻止原生菜单）：重命名/配色/删除入口是 hover 时淡入的按钮排；根画布不渲染重命名与删除按钮（而非菜单项禁用）。
- 画布节点操作按钮为 hover 淡入（0.15 秒）且位于节点顶部外侧；点击前先 `mouse_move` 到节点中心并等待动画结束，再按 `title` 定位按钮。
- 画布「删除画布」是逻辑删除且无确认框；「永久删除」与「清空回收站」才会弹确认框。
- 自动布局为 300ms rAF 动画后批量提交，断言前等待 ≥1 秒；按钮在布局期间 `disabled`。
- 宇宙视口 `viewport_set` 有 500ms 防抖且组件卸载时 flush；本用例仅验证「进入画布再返回」的保持性，不做重启落盘验证（落盘依赖用户数据库保存）。
- 画布重名校验在后端（全库唯一，`CanvasNameAlreadyExists`），前端仅做空值禁用。
- 根画布保护仅由后端 `RootCanvasCannotBeDeleted` 兜底，UI 无入口，故该错误码不在本用例触达范围。
- 子画布在宇宙中的初始位置由后端环形布局算法决定（半径 240 起、8 等分角），脚本不硬编码坐标，按文本定位。
- 配色对话框的色块为 1.5rem 方块；2026-09-21 修复后以 `role="button"` + `aria-label` 入树：预设组合色块的可访问名称为预设名（「蓝」「绿」等，即 tooltip 文案），亮/暗字段色块为「亮色主题/暗色主题 + 字段名」；hover 某色块后其 tooltip 以 `role=tooltip` 节点在可见期间入树。脚本以 UI 树 role=button + name 定位色块、以 role=tooltip 节点断言 tooltip 显隐，点击后以对话框「背景」字段值（`#e3f2fdff` / `#1e3a5fff`）与节点区域像素主色作确定性断言。
- 拖拽创建画布数据节点落点不做 20px 吸附（`screenToFlowCoordinate` 直出），节点位置可能含小数。
- 回收站面板的 v-click-outside 行为：点击画布节点 hover 按钮组的任一按钮、或点击确认框中的「取消」「确认」都会使面板关闭；确认框打开期间面板被遮罩从 UI 树过滤。因此脚本每次进行面板内操作前重新打开面板（已打开时不重复点击以免 toggle 关闭），F4 的「条目仍保留」在重开面板后断言。
- 根画布在后端的真实名称是常量 `root`，前端显示为本地化的「根画布」；重命名冲突只能以 `root` 触达。

## 修订记录

1. **F2 重名目标由「根画布」改为 `root`**：根画布在后端的真实名称是常量 `root`（见 `src-tauri\src\business\user_database\canvas\service\initialize.rs`），「根画布」只是前端本地化显示名。实测重命名为「根画布」会成功并在宇宙中出现两个同名显示节点，无法触达 `CanvasNameAlreadyExists`；预期 snackbar 正文相应改为「名为“root”的画布已存在，请更换名称」。
2. **步骤 20（原表）改为修订表的步骤 21**：原步骤 18 已把「子画布一」永久删除，宇宙中不再存在该画布，无法「再次逻辑删除『子画布一』」。修订为：步骤 20 后在根画布中重新拖拽创建子画布（默认名「新画布」），返回宇宙逻辑删除它，再执行清空回收站。
3. **步骤 9 的色块核对方式**：VTooltip 的悬浮层不出现在 UI 树中，无法按文本断言 tooltip「蓝」；修订为「点击色块后断言对话框内亮色/暗色『背景』字段值变为 `#e3f2fdff` / `#1e3a5fff`」，并以截图像素比对（浅色主题主色 `rgb(227,242,253)`）确认节点背景配色生效；tooltip 仅作截图目视核对。
4. **步骤 15-19 的面板交互补充**：点击画布节点 hover 按钮组、确认框的取消/确认都会关闭回收站面板，确认框打开期间面板被遮罩过滤；相关断言（条目保留、回收站为空）在重新打开面板后进行，脚本以「面板是否关闭」为条件决定是否重新点击回收站按钮。
5. **步骤 8 的对话框内容**：「历史组合」区块仅在已有历史配色时渲染；fixture 无历史配色，本次对话框不出现该区块，断言集合改为「预设组合」「保存」「取消」。
6. **（2026-09-21 修复追溯）步骤 8-9 色块改为 UI 树定位与 tooltip 入树断言**：应用修复（2026-09-21）第 3 条修复了原「无文本锚点的色块与 tooltip」能力边界——`ColorPairSwatch` 预设色块补 `role="button"` 与 `:aria-label="tooltip || undefined"`，`ColorFieldEditor` 字段色块补 `role="button"` 与 `:aria-label="swatchAriaLabel ?? label"`，两个配色对话框为亮/暗两栏传入「亮色/暗色 + 字段名」的 `swatch-aria-label`，`ui_tree_bridge.js` 对 `role="tooltip"` 悬浮子树在可见期间豁免遮挡判定。脚本相应修订：删除「按『预设组合』标题相对坐标推算色块位置」，改为 role=button + name 定位（预设名、亮/暗字段名）；新增「预设 7 个名称与亮色/暗色各 6 个字段色块均以 role=button + name 入树」「hover『蓝』后 UI 树出现 role=tooltip 节点且文本为『蓝』」「鼠标移开后 tooltip 节点消失」三条断言；原「背景字段值回填」与节点区域像素主色断言保留。本修订记录取代修订记录第 3 条中「以相对位置定位色块、tooltip 仅截图目视」的执行方式（第 3 条保留以便追溯）。
