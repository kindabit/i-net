# case_005 节点字段与字典（修订版）

## 测试主题

在编辑节点对话框中完成字段的增删改查：字段名与类型编辑、值输入、字段名空/重名校验；字典管理对话框全流程（添加根/子条目、删除、保存、未保存确认、空值校验）；字段绑定字典后的候选选择；密码生成器；字段值复制与剪贴板倒计时进度条。本用例验证「字段编辑 → 字典维护 → 值来源联动 → 敏感值复制」链路。

## 前置条件

- 复制 fixture `base` 到 `<case>\output\data` 并以该目录启动应用
- 解锁 `zz-e2e-base` / `e2e-password`，位于根画布（若停在画布宇宙则双击「根画布」进入）
- 界面语言：中文
- 剪贴板清空超时为默认值 10 秒（不修改设置；case_014 才修改）

## 覆盖范围

前端功能点：
- 编辑节点对话框字段区：「添加字段」新增行、字段名单击进入内联编辑（Enter 提交、Esc 取消）、字段类型下拉（按底层类型分组）
- 值编辑器按类型切换（单行文本 / 密码）；密码编辑器显示/隐藏与密码生成器入口
- 字段校验：空字段名「字段名不能为空」、重名「字段名重复」（首次出现行与重复行均标错）
- 字典管理对话框：添加根条目、添加子条目、条目值编辑、删除条目确认（含/不含子条目两种文案）、保存、空值校验、未保存修改关闭确认
- 字段的字典绑定（齿轮面板内 TreeSelect），绑定后值编辑器出现候选（VCombobox）并可选择
- 字段值复制按钮（无 title，行内定位）→ snackbar「字段值已复制到剪贴板」+ App 顶部剪贴板倒计时进度条
- 倒计时结束由前端调用后端清空系统剪贴板

后端命令（经由 UI 触发）：
- `user_database_node_field_get` / `user_database_node_field_set`（字段读取与整体替换）
- `user_database_dictionary_list` / `user_database_dictionary_set`（字典读取与整体替换）
- `clipboard_clear`（倒计时结束清空剪贴板）
- `preference_get`（读取 `clipboard_clear_timeout`，默认 10 秒）
- `user_database_node_list`（关闭对话框后重载节点）

## 备注与风险

- 字段行内按钮（齿轮、删除、复制、生成器、显示/隐藏）均无 `title`/`aria-label`，UI 树只能按「字段名文本 bounds 与本行按钮的相对位置」定位：齿轮与删除按钮位于字段名行（与名称文本 y 重叠、位于其右侧，按 left 升序分别为齿轮、删除）；复制按钮位于值行（值行 = 类型下拉所在行，取最右侧 BUTTON）；生成器按钮位于值行内（`I role=button`，按 left 升序为眼睛、魔术棒）。这是本用例最大风险点，执行时每步结合截图核对。
- 节点字段的字典绑定入口是字段名行内齿轮按钮展开面板（界面无「高级选项」文案）；模板字段（case_009）的类型行有展开区。
- 复制字段值的 snackbar 文案「字段值已复制到剪贴板」「复制失败，请手动复制」为源码硬编码（不在 i18n 文件中）。
- 剪贴板倒计时进度条位于 App 顶部，动画时长等于 `clipboard_clear_timeout` 秒（默认 10）；到时调用 `clipboard_clear`。断言前先确认顶部无进度条再开始计时。
- 字典树控件只显示「有子节点的条目」为可绑定节点；绑定后候选值为该条目直接子节点的值。
- 密码生成器长度默认 20、滑块范围 8–64；本用例不调整滑块，仅验证「使用」回填。
- 字典管理器打开时深拷贝数据，未保存修改不影响已保存数据；删除条目确认框对含子条目条目使用「其全部子条目将一并删除」文案。
- 字段类型切换为同类底层类型（字符串）时值保留；切换到底层类型不同的类型时值被清空（本用例未跨底层类型切换）。

## 修订记录

1. **字段名占位定位（步骤 2）**：计划原文按 `title="点击编辑字段名称"` 定位字段名占位。实测该元素（`.field-name-display`）在 UI 树中被作为纯文本节点提升，`title` 属性不出现；改为按占位文本「未命名字段」/显示名文本定位。
2. **字典树条目内部元素定位（步骤 14-18、23）**：字典管理对话框的 `role=treeitem` 内部子节点（VTextField 值输入框、上移/下移/加子/删除按钮）不出现在 UI 树中（调试自动化能力缺口，已在汇报中上报）。改为按 `treeitem.bounds` 相对坐标定位：值输入框 = `(left + 120, centerY)`；行内按钮（自右向左）= 删除 `right - 40`、加子 `right - 69`、下移 `right - 99`、上移 `right - 130`（均为 centerY）。另外 VTreeview 的子条目默认折叠，添加子条目后需先点击行左端展开箭头（`left + 27`）或 `toggle`，待子条目 treeitem 出现后再输入。
3. **Esc 取消字段名编辑（覆盖范围）**：计划覆盖「Esc 取消」。实测在当前环境（WebView2 + SendInput，4 种注入方式：立即/延迟/ASCII/按下松开分离）按 Esc 均把草稿**提交**为字段名而非取消。独立 Chromium（Edge）实验证明「keyup 后移除聚焦元素」不会触发 blur，故推断为应用侧 Escape 焦点处理导致 blur 提交，疑似应用缺陷。正式脚本不对 Esc 取消做通过性断言，该发现单独上报，待验收方定性。（应用已于 2026-09-21 修复，本修订随之取消规避，见修订 10。）
4. **复制验证顺序（步骤 10-12）**：为在有限倒计时周期内验证两个字段值，调整为：重开对话框后先复制「口令」值（断言 20 位字母数字）并等待倒计时结束；再复制「用户名」值（断言 `alice`）并等待倒计时结束。步骤 12 的进度条与剪贴板清空断言在两次复制中均覆盖。
5. **顶部进度条断言方式**：计划仅要求截图留档；修订为像素断言（复制前顶部无绿色像素、复制后出现大量绿色像素、倒计时结束后再次消失）。
6. **F3 后空条目删除确认文案**：空条目的 value 为空字符串，确认框正文为「确定要删除条目""吗？引用它的字段将解除字典绑定。」（计划步骤 17 的相同文案，执行时按此断言）。
7. **补充 F4 确认放弃路径（步骤 18b）**：覆盖「未保存修改确认框 → 确认 → 放弃关闭」，并验证放弃后的数据仍为已保存版本。
8. **字段名 Esc 之外的内联编辑取消路径**：Enter 提交与失焦提交保持计划原样；Esc 取消如修订 3 所述。
9. **点击确认时编辑态输入框会先失焦提交**：实测若字段名编辑态未按 Enter 而直接点击「确认」，失焦会先提交草稿再执行校验；正式脚本在编辑后统一按 Enter 提交，F1 空字段名场景不进入编辑态。
10. **新增 Esc 取消通过性断言（应用修复后，2026-09-21）**：应用修复（2026-09-21）第 1 条落地，「字段名内联编辑按 Esc 提交草稿」已修复（`NodeField.vue`：新增 `cancelRequested` 取消标记；Esc 处理由 `keyup` 移到 `@keydown.esc`，执行 `preventDefault` + `stopPropagation` 并置位标记；`commitNameEdit` 失焦提交增加取消守卫）。本脚本在 S6 原有流程内新增通过性断言序列：进入字段名编辑并输入草稿「临时草稿」→ 按 Esc → 断言草稿未写回（无「临时草稿」文本）、展示恢复为「未命名字段」、编辑节点对话框保持打开；再次编辑输入「暂存字段」→ Enter 提交并断言展示新名；点击「确认」保存并重开对话框，断言「暂存字段」已持久化、「临时草稿」未写库；随后删除临时字段行恢复现场，继续原有 F1/F2 及后续全部断言（不降低任何既有断言强度）。
