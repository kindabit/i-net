# case_015 保存与退出链路（修订版）

> 本文件是 `case_015_保存与退出链路.md` 的修订版，记录并固化了与实测一致的计划内容；
> 修订点见文末「修订记录」。正式脚本：`e2e\script\case_015\case_015.js`。

## 测试主题

覆盖用户数据库的保存与退出链路：Ctrl+S 保存提示、右下角「保存并退出」、原生窗口关闭拦截确认对话框（取消 / 不保存直接关闭 / 保存并关闭三个按钮的实际语义）、以及 registry `lastScene` 的落盘与重启恢复。本用例通过多段应用会话验证「保存 → 退出 → 重启 → 场景与数据恢复」的完整性。

## 前置条件

- 复制 fixture `base` 到 `<case>\output\data` 并以该目录启动应用（本用例会在同一数据目录上多次重启应用；会话之间不清理该目录）
- 解锁 `zz-e2e-base` / `e2e-password`，位于根画布（若停在画布宇宙则双击「根画布」进入）
- 界面语言：中文
- 脚本库需支持在同一用例内多次启动/停止应用（`launch` / `stop` 分段调用），并能检测进程退出（/health 不可达）

## 覆盖范围

前端功能点：
- Ctrl+S 保存（无独立保存按钮）与成功 snackbar「数据库已保存」
- 右下角「保存并退出」按钮：保存 → 关闭数据库 → 路由回首页（应用不退出）
- 原生窗口关闭拦截（`onCloseRequested` → `preventDefault`）与「关闭数据库」确认对话框（persistent）三个按钮：
  - 「取消」：仅关闭对话框，应用继续运行
  - 「不保存，直接关闭」：`lifecycle_close` + 窗口 `destroy`（未保存修改丢弃）
  - 「保存并关闭」：先 `lifecycle_save` 再关闭（修改保留）
- registry `lastScene`：进入画布时写入；重启解锁后按 `lastScene` 恢复场景
- 关闭数据库不保存时 `lifecycle_close` 清空内存状态后退出，不触发用户数据库的 exit-save

后端命令（经由 UI 触发）：
- `user_database_lifecycle_save`（Ctrl+S、保存并退出、保存并关闭）
- `user_database_lifecycle_close`（保存并退出、不保存关闭、保存并关闭）
- `user_database_registry_get` / `user_database_registry_set`（`lastScene`）
- `user_database_node_create` / `user_database_node_modify`（构造与验证修改）
- 退出时后端自动执行 `preference_save` / `metadata_save` / 用户数据库保存（`RunEvent::Exit`，非 UI 命令）

## 备注与风险（实测）

- **Alt+F4 可用**：实测 `key_click(["Alt","F4"])` 能触发 `onCloseRequested` 拦截并弹出 close-confirm，
  无需坐标点击原生标题栏（计划中的坐标推算方案作为备用，未启用）。
- close-confirm 为 `persistent` 对话框：实测 Esc 不关闭，只能点三个按钮之一。
- 「保存并退出」（右下角按钮）不是退出应用，而是保存 → 关闭数据库 → 回首页；「保存并关闭」才销毁窗口。
- **用户数据库为内存库**：打开时解密反序列化到内存连接，所有修改（包括拖拽创建节点）只有在
  `lifecycle_save` 之后才写回加密数据库文件。因此「不保存，直接关闭」会丢弃**全部**未保存修改
  （实测：步骤 5 创建的节点若未保存，在会话 2 中与改名修改一并丢失）。这是修订 1（步骤 5b）的原因。
- **lastScene 落盘路径**：路由变化时前端调用 `user_database_registry_set` 写内存 registry，
  随 `lifecycle_save` 一并落盘；会话 1 的步骤 2/3 保存保证了步骤 4/10/14 的恢复。
- 关闭流程不调用 `preference_save` / `metadata_save`（前端无此调用）；偏好与元数据由后端退出事件
  统一保存。「不保存，直接关闭」在 `lifecycle_close` 之后退出，此时用户数据库 `is_open=false`，
  退出保存不会写用户数据库文件。
- `/shutdown` 走正常退出流程（不经过关闭拦截对话框），仅用于最终收尾。
- 多段会话使用同一 `output\data` 目录，脚本在每段会话间不要清理该目录。
- 「退出前截图」实现为点击对话框按钮**之前**截图：点击后窗口立即销毁，无法再取帧。
- 删除画布（F5）与保存失败（F4）按计划不构造。

## 修订记录

1. **步骤 5 拆分为 5a/5b 并新增 Ctrl+S 保存基线（核心修订）**：原计划步骤 5 创建的「关闭测试」节点
   在步骤 9「不保存，直接关闭」前从未保存。实测（`.temp\e2e-run\probe_015.js`）证明用户数据库为
   内存库，未保存的节点创建与改名会一并丢失：会话 2 解锁后子画布为空（`关闭测试` 与 `丢弃修改` 均
   不存在），原计划步骤 11「节点标题为关闭测试」与步骤 12「双击节点改名」均无法成立。修订为
   步骤 5b 按 Ctrl+S 保存基线，使步骤 8 的「丢弃修改」成为唯一未保存修改，F2 语义可验证。
2. **步骤 1 的 lastScene 预期精确化**：原计划「`lastScene` 已写入子画布 id」改为「写入内存 registry，
   落盘由步骤 2/3 的保存完成；场景恢复在步骤 4（同会话重解锁）与步骤 10/14（跨会话）验证」。
3. **步骤 6 补充 Esc 断言**：计划备注中的 persistent 语义（Esc 与遮罩不关闭）由脚本显式断言
   （按 Esc 后对话框仍在）。
4. **步骤 7 补充断言**：F1 除「应用存活」外，补充「仍在子画布（UI 树可访问）」与「已保存节点
   『关闭测试』仍在」，覆盖「取消不改变任何状态」。
5. **步骤 11/14 断言集合细化**：F2 明确断言「`关闭测试` 保留 + `丢弃修改` 丢失」；F3 明确断言
   「`待保存` 保留 + `关闭测试`/`丢弃修改` 不存在」。
6. **步骤 9/13 截图时机明确**：原计划「退出前截图」实现为点击关闭按钮前截图（窗口销毁后无法取帧）。
7. **F4/F5 记录方式**：与其它用例一致，在收尾处以说明性断言记录「不构造」。
