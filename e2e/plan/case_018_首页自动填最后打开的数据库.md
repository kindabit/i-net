# case_018 首页自动填最后打开的数据库

## 测试主题

覆盖首页（`src/views/Home.vue`）「挂载时自动填入最后打开的未归档数据库名称」功能。数据源为 `metadata_list(false)`（按 `last_open_time` 降序，首项即最后打开的未归档数据库），`user_database_lifecycle_initialize` 在每次打开数据库时更新该项的 `last_open_time`。本用例通过三段应用会话验证：冷启动自动填、保存并退出回首页的重新挂载自动填、空列表不填、自动填后停留在名称步骤、归档管理对话框关闭不覆盖用户编辑、归档数据库不参与自动填。

## 前置条件

- 会话 1 以**空数据目录**启动：`--data-dir <case>\output\data`（不复制 fixture；脚本先清空 output 再启动）
- 会话 2、会话 3 在同一数据目录上重启应用（会话之间不清理该目录）
- 界面语言：中文（脚本开始时断言首页文案，若不符先经右上角语言菜单切回）
- 脚本库需支持：多段会话（`launch` / `stop` + `/health` 不可达检测）、系统剪贴板清空与读回（UI 树不返回输入框值）

## 覆盖范围

前端功能点：
- Home.vue `onMounted` 的自动填充：`await refreshMetadatas()` 后取 `metadatas[0].name` 赋给 `dbName`
  - 冷启动且存在未归档数据库：自动填最后打开的那个（`last_open_time` 最大者）
  - 列表为空：不填（输入框保持空）
  - 从数据库「保存并退出」回首页（Home.vue 重新挂载）：重新自动填
  - 归档管理对话框打开与关闭不触发重新自动填（对话框 `@update` 只刷新列表）；用户编辑不被覆盖
  - 归档数据库不参与自动填（不在 `metadata_list(false)` 返回列表中）
- 自动填后面板状态：停留在「数据库名称」步骤（不自动跳密码步骤）；点击「确认」才进入密码步
- 「确认」后的打开/新建形态判定（已注册名 → 出现「密码」输入框；未注册名 → 「创建密码」「确认密码」）
- 归档管理对话框的行内「归档」操作（`metadata_archive`）

后端命令（经由 UI 触发）：
- `metadata_list(false)`（自动填数据源；隐含断言：首项为最后打开者）
- `metadata_register`（创建数据库 A/B）
- `user_database_lifecycle_initialize`（创建并解锁 A/B；解锁 B 时更新 `last_open_time`）
- `user_database_lifecycle_save` / `user_database_lifecycle_close`（右下角「保存并退出」）
- `user_database_canvas_list`（进入画布宇宙）
- `user_database_registry_get`（读取 `lastScene`，用于进入数据库页面判定）
- `metadata_archive`（会话 2 归档 B）

**说明**：本用例不引入新的后端命令，`metadata_list` / `metadata_archive` 等均已有归属（见 `coverage.md`），本用例新增的是 Home.vue 自动填功能面的覆盖路径。

## 脚本资产需求

- 无外部图片比对资产；不需要 fixture（会话 1 要求空数据目录）
- 关键步骤截图存入 `output\`：空首页、空列表读值为空、A 创建后、保存并退出后自动填 A、B 创建后、保存并退出后自动填 B、归档对话框关闭后保留 manual、会话 2 自动填 B、密码步（打开形态）、解锁 B 根画布、保存并退出后仍填 B、B 已归档、会话 3 自动填 A

  - `clearClipboard()`：清空系统剪贴板（空输入框 Ctrl+C 不触发复制，需先清空以区分「未写入」与「残留值」）
  - 多段会话管理（`launch` / `stop` + `/health` 不可达检测，沿用 case_015 模式）

## 备注与风险（实测）

- **UI 树不返回输入值**：名称输入框的实际值只能经「聚焦 → Ctrl+A → Ctrl+C → `Get-Clipboard`」读回；空输入框的全选复制不产生选区，不会写入剪贴板，故读值前必须先清空剪贴板（实测 `Set-Clipboard -Value $null` 可用，读回为空串）。
- **`last_open_time` 精度**：A、B 的先后由操作顺序保证（B 在 A 之后创建与打开）；会话 2 步骤 13 打开 B 再次刷新其 `last_open_time`，归档操作本身不更新该时间。归档管理对话框的行顺序实测为「B 在前、A 在后」（降序的 UI 呈现），但正式脚本不断言该顺序（避免同秒时间戳时的排序歧义）。
- **「保存并退出」回首页的实现**：关闭数据库 → 路由跳转首页，Home.vue 组件重新挂载，`onMounted` 重新执行；步骤 5/8/13 验证该路径。
- **归档管理对话框**：打开与关闭均不触发 Home.vue 重新挂载（`@update` 仅刷新列表），步骤 9 验证用户编辑不被覆盖。
- **会话 3 的必要性**：验证约定 5（归档库不参与）需要在 B 被归档后重新触发一次自动填；首页无法自我重挂载，故以重启应用构造。
- **空列表下拉**：实测空数据目录下聚焦名称输入框即显示「无匹配项」，可作为「列表加载完成且为空」的状态依据（替代固定 sleep）。
- **归档操作**：归档 B 后行副标题变为「已归档」并出现「解除归档」「删除」按钮，snackbar 为「数据库“zz-e2e-018-b”已归档」；与 case_013 的观察一致。
