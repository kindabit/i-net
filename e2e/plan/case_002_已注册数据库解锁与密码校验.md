# case_002 已注册数据库解锁与密码校验

## 测试主题

在存在已注册数据库（fixture `zz-e2e-base`）的前提下解锁进入数据库：覆盖名称步自动完成候选的展示与键盘选择、密码步的内联校验与错误密码的后端错误提示、输错后重试成功，以及解锁成功后按 registry `lastScene` 恢复场景。本用例验证「首页候选 → 密码校验 → 解锁 → 恢复上次场景」主链路。

## 前置条件

- 应用启动前，将共享 fixture `_fixtures\base\data` 复制到 `<case>\output\data`（使用 `prepareDataDir(dataDir, "base")`），以该目录为 `--data-dir` 启动
- 数据库名称 `zz-e2e-base`、密码 `e2e-password`（fixture 凭据）
- 界面语言：中文（脚本开始前断言首页出现「数据库名称」，若不符先通过右上角「切换语言」菜单切回）
- fixture 的 registry `lastScene` 预期指向根画布（依据 `_fixtures\build.js` 最后停在根画布并执行 Ctrl+S）；若实测为空串，见「备注与风险」

## 覆盖范围

前端功能点：
- 名称步自动完成下拉：聚焦展开候选、候选显示数据库名称与最后打开时间（`subtitle` 为本地化 short 日期时间）
- 候选键盘操作：ArrowDown 高亮、Enter 选中并收起下拉、Escape 关闭下拉
- 名称步「确认」按钮进入密码步；已注册数据库的密码步只显示「密码」一个输入框（不出现「创建密码」「确认密码」）
- 密码内联校验：「密码不能为空」「密码长度不能少于 6 位」
- 错误密码：后端错误经 snackbar 提示「解密失败」，停留在密码步
- 输错后重试正确密码解锁成功
- 解锁成功后读取 `lastScene` 并跳转对应场景（画布存在时进入该画布）

后端命令（经由 UI 触发）：
- `metadata_list`（首页加载未归档数据库候选）
- `user_database_lifecycle_initialize`（校验密码并打开数据库）
- `metadata_save`（更新 `last_open_time` 后异步落盘）
- `user_database_registry_get`（读取 `lastScene`）
- `user_database_canvas_list`（校验 `lastScene` 对应画布是否存在）
- `user_database_registry_set`（路由场景变化时写入 `lastScene`）
- `preference_get`（启动时读取语言偏好）

## UI 操作流程与预期结果

| # | 操作 | 预期结果 |
|---|------|----------|
| 1 | 启动应用，等待首页就绪 | 出现「数据库名称」输入框与「确认」按钮；截图留档 |
| 2 | 点击「数据库名称」输入框（聚焦） | 展开候选下拉；候选项包含文本 `zz-e2e-base`，且候选项下方出现非空的最后打开时间副标题（本地化日期时间文本）；截图留档 |
| 3 | 按 Escape | 候选下拉收起，输入框仍聚焦 |
| 4 | 再次点击「数据库名称」输入框，按 ArrowDown | 第一项候选高亮（可通过截图核对高亮样式；UI 树 `states` 无文本值可直接断言） |
| 5 | 按 Enter | 下拉收起，候选 `zz-e2e-base` 被选中 |
| 6 | 点击「确认」按钮（`aria-label="确认"`） | 进入密码步；出现 label 为「密码」的输入框；不出现「创建密码」「确认密码」；「数据库名称」输入框消失 |
| 7 | 密码留空，直接点击「确认」 | 停留在密码步；密码框下方出现「密码不能为空」 |
| 8 | 点击「密码」输入框，输入 `12345`，点击「确认」 | 停留在密码步；内联提示「密码长度不能少于 6 位」 |
| 9 | 点击「密码」输入框，`Ctrl+A` 后输入 `wrong-password`，点击「确认」 | 停留在密码步；等待出现 snackbar 错误提示「解密失败」；截图留档 |
| 10 | 等待错误提示消失（最长 5 秒），点击「密码」输入框，`Ctrl+A` 后输入 `e2e-password`，点击「确认」 | 解锁成功，进入数据库页面；出现「账号 A」「备注 B」节点文本与「画布宇宙」「根画布」面包屑（`lastScene` 指向根画布时）；截图留档 |
| 11 | 检查 `<case>\output\data\user_database_set\` | 目录内用户数据库文件仍存在且未被重建（本用例不修改数据） |

## 失败路径

| # | 失败场景 | 对应步骤 | 预期结果 |
|---|----------|----------|----------|
| F1 | 密码为空提交 | 7 | 内联提示「密码不能为空」，不发起解锁 |
| F2 | 密码长度不足 6 位 | 8 | 内联提示「密码长度不能少于 6 位」，不发起解锁 |
| F3 | 密码错误 | 9 | snackbar 提示「解密失败」（`error-code.FailToDecrypt.title`），停留在密码步、不进入数据库 |
| F4 | 候选键盘选择前直接提交空名称 | 3 之后点击「确认」 | 内联提示「数据库名称不能为空」（名称被 Escape 收起下拉后仍为空），不进入密码步 |

## 备注与风险

- fixture 构建脚本 `e2e\script\_fixtures\build.js` 的最后操作序列为「回到根画布 → Ctrl+S」，因此 registry `lastScene` 预期指向根画布，解锁后应直接进入根画布。任务书原描述「lastScene 为空、解锁后进入画布宇宙」与现行 fixture 不符；本计划按直接进入根画布编写。若执行时实际停留在画布宇宙，按 fixture 状态偏差记录，断言目标仍为「进入数据库页面且出现『根画布』文本」。
- 错误密码提示为后端 `FailToDecrypt` 错误：snackbar 标题「解密失败」、正文为后端 detail（内容不固定，不断言正文）。snackbar 过渡 0.3 秒、error 停留 5 秒；断言前需确认旧提示已消失，避免新旧文本并存。
- 候选选择后输入框内容无法从 UI 树读取（`value` 不返回）；以「下拉收起 + 进入密码步后出现『密码』而非『创建密码』」间接证明候选已选中。
- 第 4 步键盘高亮不产生可断言的文本变化，以截图目视核对；如后续 UI 树暴露 `aria-activedescendant` 可直接断言。
- `metadata_save` 为 fire-and-forget，本用例不对其落盘时机做断言。
- 面板切换动画 0.22 秒；步骤 6 需等待密码步元素出现后再定位坐标。
