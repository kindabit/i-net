# e2e 测试工程指引

本目录是 i-net 的端到端测试工程：通过调试期自动化接口（见 `..\.agents\调试期自动化.md`）真实操控应用窗口，验证前端交互与后端接口的行为。

## 目录结构

- `plan\`：测试用例计划（`case_XXX_主题.md`）；计划经亲自执行修订后更新正文，并在文件末尾保留「修订记录」小节
- `script\`：公共库 `lib\`、共享 fixture `_fixtures\`、执行器 `execute.js`、用例目录 `case_XXX\`
- `script\case_XXX\`：一个用例一个目录、一个脚本（`case_XXX.js`）、脚本资产（图片、数据文件）与运行产物 `output\`（`data\` 用户数据目录、截图、`report.json`、`app.log`）
- `coverage.md`：覆盖台账，逐项对账后端命令与前端功能面
- `records\`：测试过程的屏幕录制等素材（演示 / 教学用途，不由测试流程自动生成）

## 运行方式

- 前置：`pnpm tauri:build:debug` 构建含调试自动化接口的可执行文件（内嵌前端，独立运行；不经过 vite dev server）
- 单个用例：`node e2e\script\case_XXX\case_XXX.js`（lib 直接启动预构建 exe；源码变更后必须重新构建再跑）
- 全套用例：`pnpm test:e2e`（等价 `node e2e\script\execute.js`；加 `--build` 可先构建），汇总写入 `script\output\summary.json`
- 执行期间会真实操控本机鼠标键盘；测试数据只允许使用各用例的 `output\data` 与 `.temp` 目录

## 新建用例流程：计划 → 亲自执行 → 形成脚本

1. **计划**：在 `plan\` 新建 `case_XXX_主题.md`，章节与既有计划一致：测试主题 / 前置条件 / 覆盖范围（前端功能点 + 后端命令）/ UI 操作流程与预期结果 / 失败路径 / 脚本资产需求 / 备注与风险。操作步骤要具体（点哪个按钮、输入什么文本），预期结果要可验收。
2. **亲自执行**：先真实走通计划——启动应用、注入操作、截图并目视核对（读 PNG）；计划有误时修订计划（更新计划正文并在文件末尾追加「修订记录」小节），不得在未执行的情况下直接写脚本。
3. **形成脚本**：按既有脚本的结构编写（`withApp` + `Report` + `snap` + `finalizeReport`；步骤注释标注计划编号；成功与失败路径全覆盖），运行到 PASS。
4. **覆盖对账**：把新用例接入 `coverage.md`（命令表与前端功能面表）。
5. **验证**：连续两次 PASS 后接入完整套件（`pnpm test:e2e`）。

## 覆盖要求

- 全部用例计划与脚本的并集应 100% 覆盖所有可能的前端操作与后端接口；新增功能或新接口后必须同步更新 `coverage.md`，不可覆盖项须逐条说明原因（如安全红线不构造、无 UI 入口等）。
- 无法从 UI 触达的等价入口、需要环境破坏的失败路径等，在 `coverage.md` 与用例备注中显式记录。

## 方法论（参考 `..\.agents\单元测试编码要求.md`）

- 必须同时覆盖成功路径与失败路径（前端校验、后端错误码、确认对话框取消分支等）。
- 测试条件合理但无法通过时，不得修改测试条件或被测模块使测试强行通过，必须上报。
- 用注释标注检查的测试意图；可通过合理编排测试顺序减少代码量。

## 脚本规范

- 使用 `lib\` 公共库（api / app / ui / report / image / util / paths / fixtures），不重复造轮子；lib 缺陷应上报而不是就地绕过。
- 应用生命周期用 `withApp` 包装，保证无论成败都经 `POST /shutdown` 收尾；lib 已内建端口预检与超时兜底清理。
- 断言用 `Report.check` 并落盘 `output\report.json`；流程异常额外截取 fatal 截图。
- 等待一律使用等待函数（`waitForTextStable` / `waitForGone` / `waitForCondition` 等）表达状态条件，不用固定 sleep 代替状态等待。
- 断言优先级：UI 树（文本 / role / bounds / states / attrs）→ 截图像素 → 文件系统产物 → 系统剪贴板读回。
- 起始数据用 `prepareDataDir(dataDir, "base")` 复制 `_fixtures\base\data`；需要新 fixture 时在 `_fixtures\` 下新增目录、数据与 README 说明。
- 中文 JSDoc 注释；脚本头部注释写明流程与规范要点。

## 交互陷阱与经验（实现与调试必读）

- **请求间按键不保持**：每个 `/input` 请求结束会释放仍按下的键；按住 Alt 等修饰键的拖拽必须在同一请求内完成按下 → 操作 → 松开。
- **消息过渡**：Vuetify 错误/提示切换时新旧文本会短暂并存；用 `waitForTextStable`（命中后静止复查）并追加旧提示的 `waitForGone` 断言。
- **截图帧延迟**：`/screenshot` 相对 DOM 约有数帧延迟；截图前确保目标状态稳定。像素断言要用轮询（渐变类元素颜色随动画变化，单帧判定会误判）。
- **hover 按钮离场残留**：鼠标离开后悬浮按钮仍有离场动画；操作前先移空白清场，并校验按钮 bounds 属于目标元素（否则会误点上一个元素的同名按钮）。
- **选中叠层遮挡**：多选状态会把选中节点从 UI 树过滤；读取坐标前先取消选中，或用像素断言选中态。
- **注入事件合并**：快速拖拽后立即松开可能丢失最后的 mousemove；拖拽采用分阶段移动并在松手前等待约 400ms。
- **对话框关闭动画**：关闭过程中遮罩会短暂过滤底层元素；点击前等待目标元素重新可见。
- **无文本锚点控件**：色块 / 滑块等优先用 role + name（aria-label）定位；不可用时用相邻文本相对坐标 + 字段值 / 像素断言。
- **UI 树不返回输入值**：读值用“聚焦 → Ctrl+A → Ctrl+C → PowerShell `Get-Clipboard`”；空选区不会触发复制。
- **虚拟滚动与裁剪**：列表项不在视口时先滚动到可见；UI 树会丢弃被裁剪/被遮挡的条目，断言要基于可见项或派生条件。
- **原生输入控件**（`type=date` / `type=number`）：整串注入可能被分段吞并，按段输入或逐字符实测。
- **同名文本干扰**：副标题、面板项等可能与目标重名；用 bounds 区域过滤或精确文本 / 子树文本区分。
- **复合节点**：`treeitem` 内部控件在其 UI 子树中，`treeitem` 自身无聚合 text，用子树文本判断。
- **拖拽与连接**：模板面板手柄按 `attrs.title` 定位；节点连接桩按 `attrs["data-handlepos"]` 过滤并取与节点中心线最近者。
- **边无独立 UI 树锚点**：无标签时按两端连接桩中点右键并做小范围偏移重试；有标签后按标签中心。
- **影子虚拟边**：已以 `role=button` + hint 文案入树；入向 / 出向按 bounds 相对卡片分侧。
- **构建差异**：e2e 使用 `tauri:build:debug` 产物（生产前端构建），`#if [DEBUG]` 的调试叠层不存在，不能依赖调试浮层读画布坐标。
- **进度阶段的可见窗口**：备份 / 还原的部分阶段事件可能背靠背到达而被前端批处理合并（UI 窗口为零）；断言应为“可观察阶段的有序子集”或按分支处理，不能假设每个阶段都可观察。
- **原生标题栏不在 UI 树**：窗口关闭请求用 `Alt+F4` 触发（与点击标题栏关闭按钮等价）；`Esc` 与遮罩通常不关闭 persistent 对话框。
- **按键名**：不区分大小写，支持 `Up`/`Down`/`Left`/`Right` 与 `ArrowUp` 等 W3C 名、`Enter`/`Escape`/`Tab`/`Space`/`Delete` 等。
- **运行卫生**：连续同文案的 snackbar 先等旧消息消失再断言新消息；用例运行前清空自己的 `output\`；临时脚本与产物放 `.temp` 并及时清理；多会话用例要等 `/health` 不可达后再启动下一段。

## 失败处理

- 疑似应用 bug（测试条件合理但无法通过）：立即停止并保留截图与报告，向调用方上报，不得改测试条件强行通过。
- 调试自动化接口能力缺口：上报，不要无声绕过（本次会话中的手柄 / 连接桩 / treeitem / 键名 / 色块缺口均已修复并有覆盖）。
- 修复应用代码后：先 `pnpm tauri:build:debug` 重建再重跑受影响用例；涉及 UI 树、输入注入等模块行为变化时，检查既有用例是否需要按新能力升级断言。
